# Forge of Fate · 链上实现与验证

[返回项目总 README](../README.md)

本目录集中管理链上合约、客户端交易恢复、服务器链服务、部署工具、测试与计划。**NFT 使用 ETH 交易；游戏金币留在服务器。日常网络为 Sepolia，充值暂缓。**

更新于 **2026-10-30**。核心 NFT / 市场与部署工作台已具备自动化验证；真实 MetaMask + Sepolia 部署、双钱包交易和交付证据仍需验收。

## NFT 和钱怎样流转

1. 玩家拥有的武器达到 +50 后永久封存，服务器保留固定武器记录。
2. 已签名绑定的钱包领取 10 分钟有效的铸造授权；合约核验网络、合约地址、部署标识、接收方和全部武器参数。
3. 玩家付 Gas 调用已有合约铸造，`tokenId = uint256(weaponId)`。同一部署中不能重复铸造同一武器。
4. 持有人自行填正数 ETH 价格；买家同时承诺看到的卖家和价格，旧挂单不会按新价格偷偷成交。
5. 成交原子转移 NFT，并将 ETH 记入卖家合约收益。卖家主动提现；失败保留额度，其他账户无法取走。
6. 撤单只清除挂单；直接转移自动清除挂单。两者均不把 NFT 兑换成游戏金币或可强化武器。

合约与最小市场合并，无市场手续费、版税、管理员取款或升级代理。链下回收与链上交易是不同去向；游戏币不会因为钱包持有 NFT 自动增加。未来用途按“质押期间产币”另行实现。

## 确认、历史与恢复

| 层次 | 依据 | 当前处理 |
|---|---|---|
| 钱包已广播 | 已知交易哈希 | 持久保存原网络、合约、部署标识和发送钱包 |
| 已打包 | 规范链回执 | 状态为待最终确认，不能重复提交或认定已失败 |
| 最终结果 | 回执区块达到 `finalized` | 成功/失败才清理对应待确认记录；local 测试使用 latest |
| 历史已同步 | 监听处理游标 | 与提交/回执分开展示，不用“历史没出现”推断交易失败 |

RPC 失败、回执不匹配、区块暂时变化时保留记录。切换部署或游戏账号不会删掉另一环境的记录；切回来继续检查。关闭本机服务不停止 Sepolia 交易。

已知限制：普通游戏尚不追踪替换哈希，也不恢复钱包广播后未返回哈希的情况；localStorage 无法跨浏览器迁移或抵抗用户清空站点数据。部署工作台具有自己的固定计划/哈希恢复机制，不能用它的测试替代所有游戏交易发送测试。提现没有独立事件，历史页面不等同于完整 ETH 流水。

NFT 市场列表按指定区块读取快照，但跨页的块号快照尚未绑定块哈希；短时重组或列表过期仍可能造成展示滞后。合约购买必须再次核对卖家、价格与持有人，避免按陈旧列表错误成交。

## 运行与验证

以下在项目根目录执行：

```sh
npm run check:sepolia
npm run deploy:console
npm run start:demo
```

后两个命令使用不同终端。游戏地址为 `http://127.0.0.1:5173/`，部署工作台为 `http://127.0.0.1:5174/deploy`。实际部署由 MetaMask 确认；最终确认后生成 `.local/sepolia/deployment.json`，重启游戏以加载合约和监听。

```sh
npm test
```

全量入口包括合约、后端、部署服务、客户端交易记录、全部浏览器交互、翻译、故事、生产构建/素材和独立链闭环；报告保存于 `.local/test-runs/`。详细计数、修复与覆盖范围见[本轮测试记录](测试与交易审查记录.md)。测试不会使用当前游戏数据库或真实 Sepolia 转账。

不要删除 `.local/sepolia/mint-key`、原部署计划或数据库来“重试”；已有合约的授权身份不会随本机重置自动改变。
