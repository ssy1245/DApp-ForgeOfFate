# Forge of Fate · 链上交易实施状态与下一步

[← 返回项目总览](../README.md)

更新日期：2026-10-30。本文是链上部分的状态总览；业务细则见[开发计划](链上功能与开发计划.md)，实际启停步骤见[部署指南](Sepolia部署与本地服务指南.md)。

## 本轮优先事项：账号与钱包一对一绑定

已确认：一个游戏账号同一时间只绑定一个钱包，一个钱包同一时间只绑定一个游戏账号。先完成此项，再继续 NFT 业务部署。普通玩法仍可不连接钱包；绑定前先注册或登录游戏账号。

绑定必须由服务器生成一次性消息，包含账号、钱包、网站、网络、用途和有效期，并关联当前登录会话；玩家在 MetaMask 签名，服务器验签成功才建立关系。连接钱包、填写地址、提供交易哈希都不能作为控制权证明。绑定签名不收 Gas，也不授予付款权限。

玩家身份、武器和资源保留在原存档，钱包另表关联；不得因绑定或切换钱包合并、搬动存档。双方唯一性由后端及数据库共同保证，并发请求也不能绕过。已绑定其他账号的钱包拒绝绑定；同一账号验证原钱包可重复操作，但每条验证消息只用一次。切换 MetaMask 账户或网络只影响链上操作，不切换游戏账号。首版不提供解绑或换绑入口，后续另做完整验证流程。

本轮实现与验收结果见项目 README 的[钱包注册绑定与支付](../README.md#钱包注册绑定与支付)。NFT 价格、交易币种和质押参数不因本次绑定规则而自动确定；现有合约使用测试 ETH 属于实现现状。

**当前结论：账号与钱包一对一签名绑定已实现；方案在本机按需演示的范围内可行，NFT 铸造与交易已经跑通过隔离本地链；Sepolia 目前完成了网络配置和验证合约部署入口，尚未完成 NFT 业务部署接入。图片已经接好，接下来应补 NFT 业务部署与真实钱包验收。充值仍暂缓，质押和游戏币流水尚未实现。**

这里区分三种证据：源码已实现、隔离测试通过、真实 MetaMask / Sepolia 操作已验收。前两项不能替代第三项。本轮实现与测试围绕钱包绑定展开；真实 Sepolia NFT 部署状态仍未改变，自动测试不代替真实钱包验收。

## 1. 已确定的目标与边界

- 网络使用 **Ethereum Sepolia（11155111）**，钱包使用 **MetaMask**；Hardhat 仅用于隔离开发测试。
- 我们自行完成部署、操作和录像，提供源码、公开部署资料及交易证据；老师自行部署属于可选复现方式。
- 游戏强化、背包、游戏币在本机 FastAPI + SQLite 中处理；NFT 归属和 ETH 交易由合约执行。游戏币当前不是 ERC-20。
- 演示时启动本机前后端和监听器，结束后关闭；保留数据库、部署清单、签名密钥和扫描进度，重启连接原合约补扫。
- ETH 充值的目标是“充值合约核验订单 → 同一笔成功交易转款到项目钱包 → 后端确认后入账”。部署与收款先用同一个项目钱包，不设计定期提取充值收入的管理员步骤。
- NFT 用途采用质押产币：锁入期间持续产币，取回后停产，已得游戏币不用归还，累计奖励暂不封顶。产币速率、离线累计、取回条件等仍待确认。

该方案依赖本地后端保存游戏结果和签发授权，属于链上资产与链下游戏结合的 DApp；不能描述为游戏逻辑全部去中心化。服务器关闭时，链上合约仍存在，但本机网页、游戏登录、新的铸造授权和游戏币入账服务不可用。

## 3. 现有 NFT 交易到底怎么执行

### 铭刻与图片

1. 链下武器达到当前门槛 **+50**，玩家永久封存；封存是数据库操作，不是链上铸造。
2. 玩家先注册 / 登录游戏账号，再连接 MetaMask 并签名绑定钱包。一账号一钱包，绑定不移动存档、不收取 Gas，也不自动铸造 NFT。
3. 后端检查武器归属、封存状态和等级，使用该部署的授权密钥签发当前有效期为 **600 秒**的凭证；包含武器 ID、接收人、等级、URI、到期时间和部署标识，域包含链 ID 与验证合约。
4. 玩家发送 `mint` 交易并支付 Sepolia Gas。合约验证授权、接收人、有效期及重复铸造，保存 NFT 和属性快照。签名只是授权，铸造仍须成功执行链上交易。
5. `tokenURI` 是内嵌 JSON；`image` 从[公共图片映射](../assets/NFT_Pic/manifest.json)按骑士剑、刺剑、巨剑选择。图片文件托管在公开仓库，等级和名称由各把封存武器独立生成。

合约相信指定 `mintSigner` 签出的等级和 URI，并不自行重演游戏强化过程。封存后即使取消或过期未铸造，也不会自动解除封存；过期授权可在条件仍满足时重新申请，已铸造的同一武器不能重复铸造。

### 买卖与卖家收款

1. 卖家 `list` 设置正数 ETH 价格；没有单独的市场托管步骤。当前 NFT 与市场在同一合约中，不需另做市场转移授权。
2. 买家调用 `buy(tokenId, expectedSeller, expectedPrice)` 并付足价格。合约重新检查当前所有者和挂单，价格变化、卖家变化或 NFT 已转走会导致失败。
3. 成功交易原子地把 NFT 转给买家，并把成交款记到卖家的 `proceeds`；任何一步失败都不会留下半笔成交。
4. 卖家调用 `withdraw`，成交款才转到卖家钱包。卖家可提取 ETH 与游戏金币是两套余额。
5. 直接转移会清除旧挂单；`cancel` 撤单也由持有人执行。当前没有市场手续费抽成代码。

**充值款直接转入项目钱包，不等于市场成交款也进入项目钱包。** 市场目前采用卖家自行提取收益；不要因为部署钱包也是收款钱包，就把买家付给卖家的钱当作项目收入。

### 三种“确认”必须分开

| 路径 | 当前判定 | 文案与后续要求 |
|---|---|---|
| 部署工作台 | 回执和代码核验后，等待 `finalized` 再保存成功 | 此能力只证明工作台流程，不自动覆盖游戏交易 |
| 游戏 NFT 操作 | 查询成功回执，当前页面即显示成功 | 应先称“已打包”，继续核对最终确认；不要拿这一步给充值或质押发币 |
| NFT 确认历史 | 监听到 `finalized`，再保存和处理事件 | 历史可能晚于市场快照，这是两种读取边界；应清楚显示同步状态 |

最终确认边界与最新块不同，`eth_getLogs` 可按合约和区块范围查询历史；本项目用它恢复停机期间事件。[以太坊 JSON-RPC 文档](https://ethereum.org/developers/docs/apis/json-rpc/)

## 4. 当前方案行不行得通

以下是依据现有实现作出的工程判断，不是新增已确认的业务规则。

| 方案 | 判断 | 成立条件或需要补齐的部分 |
|---|---|---|
| Sepolia + MetaMask 演示 | 可行 | Sepolia 是面向应用开发的测试网；先补业务部署，再做真实钱包验收。[官方网络说明](https://ethereum.org/developers/docs/networks/#sepolia) |
| 后端只在演示时启动 | 可行 | 合约和链上交易不依赖本机持续在线；停机时本机游戏/API不可用，新授权不能签发。已签发有效凭证或已有链上资产仍可能通过其他客户端操作 |
| 保存进度后补扫 | NFT 已验证，资金业务尚未验证 | 每批事务落盘，保留部署身份和区块哈希；节点需能返回相应历史。原库与密钥丢失不能仅靠扫链还原链下余额 |
| 继续使用现有合并 NFT/市场合约 | 首版建议采用 | 不要求为课程展示先拆成四份合约；质押可以作为外部合约持有同一 NFT。若后续拆市场，需新增授权、挂单失效处理及回归 |
| NFT 图片固定公开链接 | 可用于演示 | 已锁定提交版本，老师无需上传；仍依赖 GitHub 可访问，不等于永久链上图片存储 |
| 充值同一交易转入项目钱包 | 设计可行，未实现 | 订单核验、防重放、转款失败回滚、确认后一次入账必须形成完整链路。EIP-712 本身不负责业务防重放。[EIP-712](https://eips.ethereum.org/EIPS/eip-712) |
| NFT 锁仓持续产币、取回不还币 | 设计可行，规则未齐 | 合约记录锁仓/解锁，后台按已确认区间结算；取回不应依赖后台在线或“还款签名”。接收 NFT 须正确处理安全转移回调。[ERC-721](https://eips.ethereum.org/EIPS/eip-721) |
| 游戏币只保存在 SQLite | 适合当前单机演示 | 已建立账号身份与独立钱包关联，仍需完整账本再接充值和奖励；它依赖服务器和备份，不是链上可自行兑现的代币 |

现有 `ForgeOfFate` 没有升级入口，`mintSigner` 和 `deploymentId` 固定在构造时。需要改这些内容或修改合约逻辑时，不能假设更新前端就生效，应按明确的新部署处理，并保留旧部署资料。首版是否保留合并结构尚待正式确定，上表只给出减少改动的建议。

## 5. 下一步顺序与完成标准

### P0：先验收钱包绑定，再接通 Sepolia NFT 与市场

钱包绑定已实现：登录账号后使用顶部入口，核验一对一关系、拒签、冲突、钱包切换与原存档保留。真实 MetaMask 签名验收可在 NFT 部署前进行。

这一步不需要先确定充值兑换比例或质押产币速度。

1. **固定本轮合约范围。** 建议首版保留 `ForgeOfFate` 的 NFT + 市场，卖家继续自行提取收益；决定后再生成业务部署计划。
2. **增加 NFT 业务部署模块。** 准备专用服务器铸造授权密钥并持久保存，只公开授权地址；把地址、部署标识、编译信息和构造参数固定到独立计划。MetaMask 仅使用项目钱包签名部署，私钥不进入服务器配置。
3. **核验并保存业务清单。** 最终确认后写入 `.local/sepolia/deployment.json`，包括正确 ABI、地址、链 ID、部署交易/区块/哈希、创世与代码哈希、部署标识及铸造授权地址；本机 `mint-key` 必须与该地址匹配。不要复用 Probe 目录或覆盖旧计划。
4. **对齐交易和恢复状态。** 游戏页面区分已提交、已打包、最终确认、索引完成；检查失败、拒签、加速/取消、刷新与重启。工作台已有的恢复测试不能当作 NFT 页面已经覆盖这些情况。
5. **本地先验收接入。** 验证错误网络/钱包、过期和重复授权、挂单变化、转移后旧挂单失效、接收方回调，以及恢复过程中不重复发交易。
6. **再做少量 Sepolia 操作。** 用两个钱包完成三路线图片核对、铭刻、挂牌/改价/撤单、购买、卖家提取和直接转移；保留交易链接。关闭并重启本地服务，验证同一地址、存档和 NFT 确认历史恢复。

**完成判据**：有可核查的业务合约部署、NFT 归属、买卖及卖家收益证据；页面状态和链上事实一致；启停不换合约、不丢存档、不重复操作。源码验证、钱包外部图片展示及录像也要记录实际结果。

### P1：游戏币账本，再接 NFT 质押用途

固定玩家 ID（`accounts.id`）与独立钱包绑定表已接入，旧存档键保持不变。下一步将金币购买、回收、测试发放，以及未来奖励/充值纳入同一套流水，流水、余额和业务状态在同一事务提交；明确测试资产与演示业务的使用范围。

确认质押参数后开发锁仓、取回、每次锁仓唯一编号、规则版本和事件处理；收益只结算到已完整处理的确认边界，保留上次结算位置与余数。重复扫描/结算不重复发币；停机期间已取回的 NFT 不能继续算到重启时刻。累计不封顶还需确定金额存储与前端精度方案，不能靠浮点数无限累加。

**完成判据**：NFT 真正进入合约并能由原持有人取回；有效区间内产币，取回停产，旧收益不退还；包含锁仓与解锁均发生在停机期间的恢复测试。离线收益目前只是建议，不默认作为已确认规则。

### P2：充值保持暂缓，确认参数后再接入

复用前一阶段账本，增加订单、签名报价、充值合约、即时转款、确认后入账和页面。订单号独立去重，客户端提交哈希不能代替节点核验；覆盖错误金额/付款人、过期、重复、转款失败、后台停机及入账中断恢复。

**完成判据**：有效订单的钱到项目钱包且游戏币只增加一次；链上成功但未入账可恢复，失败交易不发币。不开启退款或兑回 ETH 的隐含承诺。充值不是当前 NFT 部署的前置依赖。

### P3：演示与交付

录制已完成的 NFT 铸造、实际用途、交易和恢复；充值实现后再加入完整演示。随源码提供依赖锁文件、部署工具、公开部署资料、图片映射、空白 `.env.sepolia.example` 和操作说明。私钥、带凭据 RPC、数据库、日志不上传；在独立目录验证模板复现，不能把现有电脑的私密配置当作交付模板。

分阶段的详细待办见[开发顺序与验收](链上功能与开发计划.md#8-开发顺序与验收)。

## 6. 哪些需要讨论，哪些不必阻塞当前工作

| 事项 | 状态 / 何时需要确定 |
|---|---|
| 网络、钱包、三张图片来源 | 已确定；当前不必重新选择 |
| 账号与钱包绑定 | 一对一，先登录游戏账号再签名验证；不合并存档，首版无解绑 / 换绑 |
| NFT 价值、定价与交易币种 | 仍待讨论；现有合约使用测试 ETH，不等于最终决策 |
| 首版 NFT/市场是否拆分 | 建议保留现有合并合约；NFT 业务部署计划固定前确定 |
| 卖家收款 | 当前自行提现；建议首版保留，改即时转款需另改合约并测试 |
| 市场手续费、游戏币买 NFT | 当前无此实现；不默认添加 |
| 产币速率、是否随等级变化、精度、到账频率 | 质押实现前确定 |

| 充值比例、档位、金额范围、报价有效期、退款 | 充值实现前确定；不阻塞 NFT 部署 |

## 7. 当前可用的入口与验证证据

依赖安装与本机配置见[准备清单](开发前填写清单.md)。下面都是现有命令，不是尚不存在的业务部署指令。

| 命令 | 现在实际做什么 |
|---|---|
| `npm run check:sepolia` | 检查真实节点的链 ID 与最终确认能力，不发交易 |
| `npm run check:sepolia -- --offline` | 仅检查本机配置格式 |
| `npm start` | 启动本机 Sepolia 游戏服务；存在 NFT 清单才启动监听；启动时要求节点检查通过 |
| `npm run deploy:console` | 打开验证合约部署工作台；当前不能部署 NFT 业务 |
| `npm run indexer:sepolia -- --once` | 有匹配 NFT 业务清单时补扫后退出；当前缺少该清单不能使用 |
| `npm run verify:game` | 隔离本地链跑 NFT 铸造、交易、图片与停机恢复，不花 Sepolia 测试 ETH |
| `npm run test:contracts` / `npm run test:backend` | 验证现有合约和后端，不代表未来充值/质押已实现 |
| `npm run test:deploy:service` / `npm run test:deploy` | 模拟节点及隔离钱包环境检查工作台；不替代真实 MetaMask 扩展 |

2026-10-30 本轮验证：338 项后端、9 项双语、21 项相关浏览器检查及前端构建通过。新增绑定检查包含 15 项后端场景与 5 项浏览器场景，覆盖双向唯一、并发、签名伪造 / 过期 / 重放、跨会话、旧关联重验、拒签、切钱包不换账号和链上按钮保护。运行命令：`npm run test:backend`、`npm run test:i18n -w frontend`、`npm run test:browser -- tests/browser/wallet-binding.spec.cjs tests/browser/ui-language-layout.spec.cjs tests/browser/game-consistency.spec.cjs`、`npm run build`。

`npm run verify:game` 也已通过，隔离本地链报告为 `.local/verify-game-qFh3pV/verification.json`，包括账号绑定后的三路线 NFT 铸造、买卖、提现、转移、后端重启及停机补扫。真实 MetaMask 扩展与 Sepolia 业务部署尚未验收。本轮未运行整套浏览器检查、独立合约测试或部署工作台测试；2026-10-28 的历史验证范围保留在[测试记录](本地测试与页面数据一致性.md#5-本轮验证记录)。
