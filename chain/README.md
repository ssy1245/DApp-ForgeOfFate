## NFT 和钱怎样流转

1. 玩家拥有的武器达到 +50 后永久封存，服务器保留固定武器记录。
2. 已签名绑定的钱包领取 10 分钟有效的铸造授权；合约核验网络、合约地址、部署标识、接收方和全部武器参数。
3. 玩家付 Gas 调用已有合约铸造，`tokenId = uint256(weaponId)`。同一部署中不能重复铸造同一武器。
4. 持有人自行填正数 ETH 价格；买家同时承诺看到的卖家和价格，旧挂单不会按新价格偷偷成交。
5. 成交原子转移 NFT，并将 ETH 记入卖家合约收益。卖家主动提现；失败保留额度，其他账户无法取走。
6. 撤单只清除挂单。游戏不提供转赠入口；合约仍保留标准 ERC-721 转账能力。成交后从卖家收藏移除，最终确认监听将原封存武器归档并发出通知邮件；不把 NFT 或成交款兑换成游戏金币。

合约与最小市场合并，无市场手续费、版税、管理员取款或升级代理。链下回收与链上交易是不同去向；游戏币不会因为钱包持有 NFT 自动增加。未来用途仅按“质押期间产币”另行实现：独立质押合约托管 NFT，服务器按仓位质押人向绑定账号结算金币，取回停产；不增加 NFT 装备、远征或战斗，不兑换回可强化武器。

## 确认、历史与恢复

| 层次 | 依据 | 当前处理 |
|---|---|---|
| 钱包已广播 | 已知交易哈希 | 持久保存原网络、合约、部署标识和发送钱包 |
| 已打包 | 规范链回执 | 状态为待最终确认，不能重复提交或认定已失败 |
| 最终结果 | 回执区块达到 `finalized` | 成功/失败才清理对应待确认记录；local 测试使用 latest |
| 历史已同步 | 监听处理游标 | 与提交/回执分开展示，不用“历史没出现”推断交易失败 |

RPC 失败、回执不匹配、区块暂时变化时保留记录。切换部署或游戏账号不会删掉另一环境的记录；切回来继续检查。关闭本机服务不停止 Sepolia 交易。

已知限制：普通游戏尚不追踪替换哈希，也不恢复钱包广播后未返回哈希的情况；localStorage 无法跨浏览器迁移或抵抗用户清空站点数据。部署工作台具有自己的固定计划/哈希恢复机制，不能用它的测试替代所有游戏交易发送测试。提现没有独立事件，历史页面不等同于完整 ETH 流水。

NFT 市场列表按指定区块读取快照，但跨页的块号快照尚未绑定块哈希；短时重组或列表过期仍可能造成展示滞后。合约购买必须再次核对卖家、价格与持有人，避免按陈旧列表错误成交。

## 运行与验证

首次下载先按[项目 README 的快速启动](../README.md#快速启动)安装依赖、填写老师自己的 RPC，并选择导入[公开演示清单](../deployments/sepolia-demo.json)或独立部署。导入后，在项目根目录执行：

```sh
npm run check:sepolia
npm run start:demo
```

游戏地址为 `http://127.0.0.1:5173/`。存在 `.local/sepolia/deployment.json` 时，统一启动器同时启动监听，不要再重复运行 `indexer:sepolia`。仅需独立监听时使用 `npm run indexer:sepolia`；进度保存在本机数据库中，重启继续补扫。

老师若要独立复现铸造，在另一份全新项目目录运行 `npm run deploy:console`，打开 `http://127.0.0.1:5174/deploy`，由 MetaMask 确认部署。最终确认后生成自己的清单和授权密钥，再启动游戏。共享公开市场无需部署；公开清单不包含铸造权限。`5174` 是部署服务入口，日常账号登录和交易使用 `5173`。

```sh
npm test
```

全量入口包括合约、后端、部署服务、客户端交易记录、全部浏览器交互、翻译、故事、生产构建/素材和独立链闭环；报告保存于 `.local/test-runs/`。详细计数、修复与覆盖范围见[本轮测试记录](测试与交易审查记录.md)。测试不会使用当前游戏数据库或真实 Sepolia 转账。

不要删除 `.local/sepolia/mint-key`、原部署计划或数据库来“重试”；已有合约的授权身份不会随本机重置自动改变。

## 接下来做什么

首份 `ForgeOfFate` 已完成部署、最终确认和监听接入，公开地址与交易见[部署记录](链上功能与开发计划.md)。下一步用测试账号铭刻第一把 NFT；不要重复部署，交易恢复和业务验收的待办仍需逐项完成。

1. 完成游戏交易的加速/取消、广播结果不明时恢复，增加发送阶段的浏览器测试。
2. 已完成真实部署，继续双钱包 Sepolia 验收，保存关键交易链接。
3. 增加游戏币流水与金额精度方案，覆盖现有商店、回收、测试发放。
4. 确认质押参数后再开发锁仓、取回、区间奖励与断点结算。
5. 整理演示、备份、源码版本和交付资料；充值与 NFT 兑换回武器仍暂缓。

完整顺序及完成标准见[链上功能与开发计划](链上功能与开发计划.md)。

公开清单已从当前真实部署按字段筛选导出，并在项目 README 提供手动导入步骤；私密配置与运行数据留在本机。老师可连接同一市场交易，独立铸造则需要自己的部署与授权密钥。后续补齐配置选择与新环境切换入口，并在全新机器验收；当前切换部署使用另一份项目目录，不能覆盖旧数据库绑定的部署身份。
