# Forge of Fate · Sepolia 部署与本地服务指南

更新日期：2026-10-28。

本文件集中说明第一次怎样部署合约、平时怎样启动和关闭本地服务器、停机后如何补扫，以及哪些数据必须保留。业务与账本规则见[链上功能与开发计划](链上功能与开发计划.md)，文档目录见[链上文档导航](README.md)。

**目标已经确定为 Ethereum Sepolia + MetaMask；当前源码仍仅接通本地 Hardhat。** 本文件大部分是待实现的操作流程，最后的命令表明确列出现阶段真正可用的命令，不能把本文当作已经完成 Sepolia 部署的记录。

开始准备时先看[开发前填写清单](开发前填写清单.md)。项目根目录 `.env.sepolia` 是实际填写位置，公开模板为 [`.env.sepolia.example`](../.env.sepolia.example)。已经提供只读配置检查器，游戏和部署程序的接入仍待开发。

## 1. 两种环境

| 环境 | 用途 | 停机后如何恢复 |
|---|---|---|
| 本地 Hardhat | 开发、单元测试、隔离的完整流程验证 | 当前链进程停止后链上数据会丢失，不能靠旧扫描块号恢复。新建环境应配套新部署和隔离存档；如要保留本地链，需另做持久化/配套快照方案。 |
| Ethereum Sepolia | 已确定的演示网络，用于录制视频和保留可查交易 | 关闭的是本地程序；再次启动读取原部署、原数据库和扫描进度，补查历史。测试网若发生重置或历史不可查询，应停下并另行处理。 |

Sepolia 模式只要求本机能连接节点，不要求我们的后端有公网域名或长期在线。演示和检查由我们启动自己的环境，老师无需先部署一套才能查看视频和公开链上成果。

## 2. 第一次准备与部署：建议流程

1. 按填写清单准备 `.env.sepolia`：填写 `PROJECT_WALLET_ADDRESS` 和 `SEPOLIA_RPC_URL`，第二个演示钱包 `DEMO_BUYER_ADDRESS` 可稍后补充。已确定项目钱包同时负责部署和收款。准备 Sepolia 测试 ETH，并运行 `npm run check:sepolia` 核对配置和节点网络。
2. 安装项目依赖，保持依赖锁文件和源码版本可追溯；新建专用演示环境目录，不覆盖现有本地存档。
3. 生成或读取该环境自己的服务器授权密钥，确认公钥对应的地址；密钥与环境长期保存，不在每次启动时重新生成。
4. 按开发阶段部署已完成的合约：先完成 NFT 与市场，再增加充值和质押。引用 NFT 的合约必须使用同一环境的 NFT 地址；充值合约配置收款地址和报价验证地址。实际拆分和部署依赖在实现后固定，不要求尚未开发的模块阻塞初次链上演示。
5. 等待部署成功并记录每份合约的地址、部署交易、区块号和区块哈希，写入部署清单。
6. 检查链 ID、合约代码/版本、关联 NFT 地址、收款地址和授权地址均符合预期，再允许后台签发业务授权。
7. 保存公开部署资料和验证所需的编译设置、构造参数；在 Sepolia 区块浏览器完成源码验证，并在前端提供部署地址和交易的可核查链接。
8. 初始化该环境数据库，执行版本化迁移，把索引起点设置为对应合约的部署区块之前，然后运行首次扫描。

启动器应区分“部署新环境”与“连接已有环境”。公共测试网的普通启动不应因为节点临时不可用就偷偷重新部署或覆盖配置。

## 3. 建议的配置分类

| 配置类别 | 内容 | 保存位置原则 |
|---|---|---|
| 可公开部署清单 | 网络、链 ID、各合约地址、部署区块/交易、版本、公开授权地址、收款地址 | 可作为作业材料提交；不混入凭据 |
| 本机连接配置 | RPC 地址、端口、数据库路径、环境标识、确认/扫描参数 | 保存在本地；带 API 密钥的 RPC 地址不写入公开材料 |
| 私密配置 | 服务器签名密钥及部署所需凭据 | 本机受限文件或钱包，遵循 `.gitignore`，不进入源码、前端、日志或视频 |
| 运行数据 | 数据库、订单、流水、扫描进度、收益结算边界 | 按环境保存并备份，不因正常启停清空 |

准备配置已经采用根目录 `.env.sepolia`，由检查器读取，不把带凭据的 RPC 地址暴露给前端。建议后续以统一部署清单向前端提供公开合约信息，取消前端硬编码单一合约与 `31337` 的做法。部署清单格式和游戏运行时配置加载仍待实现；当前填好文件不会自动切换游戏网络。

## 4. 每次启动：建议流程

1. 读取选择的环境、部署清单、数据库和授权配置，检查必要文件是否存在。
2. 打开数据库并执行兼容的迁移；加载未完成的充值入账、质押结算和其他持久化任务，暂不执行发币，等待链上核验与补扫。
3. 连接节点，校验目标链、各合约身份、收款地址和授权地址。核验失败显示具体错误，不换链、不清库。
4. 启动后端与唯一的监听进程，前端先显示同步状态。
5. 读取扫描进度，验证区块哈希，按区间补查停机期间所有目标事件；发现重组按[监听与账本规则](链上功能与开发计划.md#74-确认和链重组)处理。
6. 按顺序恢复订单、NFT 所有权和锁仓区间，再处理确认后的充值与质押奖励。
7. 达到确定的同步边界、关键任务恢复后，将对应业务标记为可用。
8. 持续扫描新区块并处理待办；断网时退避重试，保存错误，恢复后继续原进度。

例：完整扫描进度为 1000，节点已到 1050。核验近期历史后分批读取 1001～1050 的目标事件，达到确认要求的部分才做最终入账；其余保留为确认中。补扫是在查询历史，不是重新发起原来的交易。

## 5. 每次关闭：建议流程

1. 标记服务器正在停止，停止接收新的充值报价等写入请求；已经签发且未过期的链上授权仍可能被使用。
2. 停止领取新的扫描和业务任务，给正在执行的数据库事务一个有界的完成时间；未完成事务回滚，持久化待办下次重试。
3. 停止监听、后端和本次启动的前端进程，记录最后完整提交的进度。
4. 使用 SQLite 备份机制或停写后的完整备份保存数据库，保留匹配的部署配置、规则版本和密钥；不要只复制正在写入的主库而遗漏 WAL 中的数据。
5. 不删除 Sepolia 部署配置，不重新生成授权密钥，不清空游戏存档。

扫描进度和订单必须在运行期间持续提交，不能只在点击“关闭”时保存。电脑异常退出也应能从最后一次提交恢复。现有启动脚本的停止行为尚未提供上述完整关闭流程。

## 6. 数据恢复边界

链上事件能帮助重建 NFT、付款和锁仓历史，**不能完整恢复服务器里的强化结果、游戏币消费、账号绑定与其他链下操作**。因此不能用“删库后重新扫链”代替恢复原存档，也不能在一个全新余额库里重复发放旧充值所得。

数据库损坏或丢失时先恢复一致的备份，再重放未处理的事件。没有足够账本证据时，暂停发币并核对，而不是猜测原余额。测试链重置、合约升级或换网络，应创建新的环境标识；是否迁移资产和余额需要单独方案。

## 7. 当前可以使用的命令

下列命令仅说明**已有本地开发流程**，不是未来 Sepolia 环境的启动说明。依赖准备和完整说明见[项目 README](../README.md#快速启动)。

| 命令 | 当前作用 |
|---|---|
| `npm run check:sepolia` | 读取 `.env.sepolia`，检查地址格式并只读核验节点链 ID；不发送交易 |
| `npm run check:sepolia -- --offline` | 只检查填写格式，不访问节点 |
| `npm start` | 启动/复用本地链、部署检查、后端与前端；不包含新的充值或质押监听 |
| `npm run start:demo` | 在本地演示模式启动；已有后台可能被复用，具体设置以当前进程为准 |
| `npm run chain` | 单独启动本地 Hardhat |
| `npm run deploy` | 向本地链部署当前单个 `ForgeOfFate`，不是 Sepolia 部署入口 |
| `npm run test:contracts` | 运行现有合约测试 |
| `npm run test:backend` | 运行现有后端测试 |
| `npm run verify:game` | 在隔离环境验证当前游戏/NFT 闭环；目前不覆盖未来充值和质押功能 |

Sepolia 部署、独立监听和恢复命令目前尚未实现，待对应阶段完成后在这里补充实际可执行命令。
