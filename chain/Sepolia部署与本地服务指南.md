# Forge of Fate · Sepolia 部署与本地服务指南

更新日期：2026-10-28。

本文件集中说明第一次怎样部署合约、平时怎样启动和关闭本地服务器、停机后如何补扫，以及哪些数据必须保留。业务与账本规则见[链上功能与开发计划](链上功能与开发计划.md)，文档目录见[链上文档导航](README.md)。

**日常启动与通用部署工作台已使用 Ethereum Sepolia + MetaMask；普通游玩在本机后端结算。** 当前工作台仅提供验证合约，本机尚无最终确认的部署记录。NFT 业务闭环只在隔离 Hardhat 验证；图片固定公开链接已接入；Sepolia NFT 业务部署、充值和质押尚待完成。下文区分当前操作与未来业务流程。

开始准备时先看[开发前填写清单](开发前填写清单.md)。项目根目录 `.env.sepolia` 是实际填写位置，公开模板为 [`.env.sepolia.example`](../.env.sepolia.example)。已提供只读检查器和 `npm run backend:sepolia` 后端入口；通用 Sepolia 部署入口已实现，见[合约部署工作台](合约部署工作台.md)，实际交易仍需人工钱包确认。开发和验收优先采用[本地测试流程](本地测试与页面数据一致性.md)。

## 1. 两种环境

| 环境 | 用途 | 停机后如何恢复 |
|---|---|---|
| 本地 Hardhat | 开发、单元测试、隔离的完整流程验证 | 当前链进程停止后链上数据会丢失，不能靠旧扫描块号恢复。新建环境应配套新部署和隔离存档；如要保留本地链，需另做持久化/配套快照方案。 |
| Ethereum Sepolia | 已确定的演示网络，用于录制视频和保留可查交易 | 关闭的是本地程序；再次启动读取原部署、原数据库和扫描进度，补查历史。测试网若发生重置或历史不可查询，应停下并另行处理。 |

Sepolia 模式只要求本机能连接节点，不要求我们的后端有公网域名或长期在线。演示和检查由我们启动自己的环境，老师无需先部署一套才能查看视频和公开链上成果。

## 2. 第一次准备与部署：建议流程

### 当前可执行的准备与验证合约部署

1. 按[项目 README](../README.md#快速启动)安装依赖，从空白模板复制并填写 `.env.sepolia`，运行 `npm run check:sepolia`。
2. 普通游玩运行 `npm start`，打开 http://127.0.0.1:5173/；无需先部署验证合约。
3. 需要验证 MetaMask 部署时，另运行 `npm run deploy:console`，打开 http://127.0.0.1:5174/deploy，按[工作台说明](合约部署工作台.md)核对并由钱包确认。只有这一步会在确认后消耗 Sepolia 测试 ETH。
4. 等最终确认，保留 `.local/sepolia/deploy-console/deployment-probe/`。这是验证合约记录，不是 NFT 业务部署，也不需要铸造授权密钥或图片配置。

### 后续 NFT、充值与质押的部署准备（尚未全部实现）

当前工作台没有 NFT 业务模块，下列步骤不能仅靠现有 Probe 页面完成；需先按[开发顺序](链上功能与开发计划.md#8-开发顺序与验收)补齐 NFT 部署入口、授权密钥和业务清单。首版建议保留合并 NFT/市场；共享账本与质押先推进，充值仍暂缓。

1. 按填写清单准备 `.env.sepolia`：填写 `PROJECT_WALLET_ADDRESS` 和 `SEPOLIA_RPC_URL`，第二个演示钱包 `DEMO_BUYER_ADDRESS` 可稍后补充。已确定项目钱包同时负责部署和收款。准备 Sepolia 测试 ETH，并运行 `npm run check:sepolia` 核对配置和节点网络。
2. 安装项目依赖，保持依赖锁文件和源码版本可追溯；新建专用演示环境目录，不覆盖现有本地存档。
3. 生成或读取该环境自己的服务器授权密钥，确认公钥对应的地址；密钥与环境长期保存，不在每次启动时重新生成。
4. [公开图片链接和元数据接入](../assets/NFT_Pic/README.md)已完成，各部署直接共用公共映射。按开发阶段部署已完成的合约：先完成 NFT 与市场，再增加充值和质押。引用 NFT 的合约必须使用同一环境的 NFT 地址；充值合约配置收款地址和报价验证地址。实际拆分和部署依赖在实现后固定，不要求尚未开发的模块阻塞初次链上演示。
5. 等待部署成功并记录每份合约的地址、部署交易、区块号和区块哈希，写入部署清单。
6. 检查链 ID、合约代码/版本、关联 NFT 地址、收款地址和授权地址均符合预期，再允许后台签发业务授权。
7. 保存公开部署资料和验证所需的编译设置、构造参数；在 Sepolia 区块浏览器完成源码验证，并在前端提供部署地址和交易的可核查链接。
8. 初始化该环境数据库，执行版本化迁移，把索引起点设置为对应合约的部署区块之前，然后运行首次扫描。

当前启动器已区分日常启动与部署工作台，`npm start` 不自动部署，节点不可用时不会重建环境。未来业务部署也须保留这一边界。

## 3. 建议的配置分类

| 配置类别 | 内容 | 保存位置原则 |
|---|---|---|
| 公共图片配置 | 固定公开图片 URL、来源提交版本、武器对应关系 | 已接入并应随源码提交；所有部署复用，不写入各自的私密环境文件。当前状态见[图片说明](../assets/NFT_Pic/README.md) |
| 可公开部署清单 | 网络、链 ID、各合约地址、部署区块/交易、版本、公开授权地址、收款地址 | 可作为作业材料提交；不混入凭据 |
| 本机连接配置 | RPC 地址、端口、数据库路径、环境标识、确认/扫描参数 | 保存在本地；带 API 密钥的 RPC 地址不写入公开材料 |
| 私密配置 | 服务器签名密钥及部署所需凭据 | 本机受限文件或钱包，遵循 `.gitignore`，不进入源码、前端、日志或视频 |
| 运行数据 | 数据库、订单、流水、扫描进度、收益结算边界 | 按环境保存并备份，不因正常启停清空 |

实际配置使用根目录 `.env.sepolia`。检查器与 `npm run backend:sepolia` 会读取它；后者将节点地址传给后端，并固定选择 `.local/sepolia/`，不与 `.local/game.sqlite3` 混用。数据库通过 `runtime_environment` 记录所属网络，跨网络启动会拒绝；原本地旧库首次升级归为 local。前端从 `/api/config` 读取公开网络与合约信息，从 `/api/chain/nfts` 和 `/api/chain/receipts/{hash}` 查询 NFT 与回执，不接收私密 RPC。

NFT 业务部署清单沿用 `address`、`chainId`、`deploymentId`、`mintSigner`、`abi` 的单合约格式，保存为对应环境的 `deployment.json`；授权密钥在同目录 `mint-key`。后端会核对链 ID、合约代码是否存在、部署标识与授权地址，签发凭证前检查本机密钥匹配。没有清单或校验失败时，只读合约接口和铸造授权不可用，不会偷偷部署或生成新密钥。清单版本 2 已增加创建交易、部署区块、创世与代码哈希，监听会核对并保存 NFT 事件和补扫进度。Sepolia 对应 NFT 清单尚未生成。验证合约清单位于 `.local/sepolia/deploy-console/deployment-probe/deployment.json`，不得复制成 `.local/sepolia/deployment.json`。多合约与资金恢复仍待实现，详见[链上监听与恢复](链上监听与恢复.md)。

## 4. 每次启动：建议流程

**当前操作**：保留原 `.env.sepolia` 和 `.local/sepolia/`，运行 `npm start` 或 `npm run start:demo`。启动器检查节点后启动本机后端与前端；只有存在 NFT 业务清单时才启动监听。部署工作台按需单独运行，读取原计划与交易状态。

**未来含充值 / 质押的完整恢复流程**（当前只实现其中的环境核验和 NFT 事件补扫）：

1. 读取选择的环境、部署清单、数据库和授权配置，检查必要文件是否存在。
2. 打开数据库并执行兼容的迁移；加载未完成的充值入账、质押结算和其他持久化任务，暂不执行发币，等待链上核验与补扫。
3. 连接节点，校验目标链、各合约身份、收款地址和授权地址。核验失败显示具体错误，不换链、不清库。
4. 启动后端与唯一的监听进程，前端先显示同步状态。
5. 读取扫描进度，验证区块哈希，按区间补查停机期间所有目标事件；发现重组按[监听与账本规则](链上功能与开发计划.md#74-确认和链重组)处理。
6. 按顺序恢复订单、NFT 所有权和锁仓区间，再处理确认后的充值与质押奖励。
7. 达到确定的同步边界、关键任务恢复后，将对应业务标记为可用。
8. 持续扫描新区块并处理待办；断网时退避重试，保存错误，恢复后继续原进度。

例：完整扫描进度为 1000，节点已到 1050。核验近期历史后分批读取 1001～1050 的目标事件，达到确认要求的部分才做最终入账；其余保留为确认中。补扫是在查询历史，不是重新发起原来的交易。

## 5. 每次关闭：建议流程

**当前操作**：在游戏、工作台及独立监听各自的终端按 Ctrl+C。启动器停止自己创建的子进程；保留数据库、原部署目录和配置。数据库备份方法见[主 README](../README.md#数据结构升级与备份)。这不停止 Sepolia 本身。

**未来含资金业务的完整关闭要求**：

1. 标记服务器正在停止，停止接收新的充值报价等写入请求；已经签发且未过期的链上授权仍可能被使用。
2. 停止领取新的扫描和业务任务，给正在执行的数据库事务一个有界的完成时间；未完成事务回滚，持久化待办下次重试。
3. 停止监听、后端和本次启动的前端进程，记录最后完整提交的进度。
4. 使用 SQLite 备份机制或停写后的完整备份保存数据库，保留匹配的部署配置、规则版本和密钥；不要只复制正在写入的主库而遗漏 WAL 中的数据。
5. 不删除 Sepolia 部署配置，不重新生成授权密钥，不清空游戏存档。

扫描进度和订单必须在运行期间持续提交，不能只在点击“关闭”时保存。电脑异常退出也应能从最后一次提交恢复。现有启动脚本的停止行为尚未提供上述完整关闭流程。

## 6. 数据恢复边界

链上事件能帮助重建 NFT、付款和锁仓历史，**不能完整恢复服务器里的强化结果、游戏币消费、账号绑定与其他链下操作**。因此不能用“删库后重新扫链”代替恢复原存档，也不能在一个全新余额库里重复发放旧充值所得。

数据库损坏或丢失时先恢复一致的备份，再重放未处理的事件。没有足够账本证据时，暂停发币并核对，而不是猜测原余额。测试链重置、合约升级或换网络，应创建新的环境标识；是否迁移资产和余额需要单独方案。

## 7. 当前可以使用的命令

下列命令说明**当前可用能力**，默认入口已用于 Sepolia 本机游戏与通用部署，NFT 业务部署和资金结算尚未完成。依赖准备和完整说明见[项目 README](../README.md#快速启动)。

| 命令 | 当前作用 |
|---|---|
| `npm run check:sepolia` | 读取 `.env.sepolia`，检查地址格式、节点链 ID 和 finalized 能力；不发送交易 |
| `npm run deploy:console` | 启动 Sepolia MetaMask 部署页面；固定保存部署计划，实际交易由钱包确认 |
| `npm run test:deploy` | 独立本地链公共部署检查 + 模拟 Sepolia 页面检查，不操作真实扩展或发送 Sepolia 交易 |
| `npm run test:deploy:service` | 使用模拟 RPC 检查 Sepolia 最终确认、记录恢复和节点失败，不发送交易 |
| `npm run check:sepolia -- --offline` | 只检查填写格式，不访问节点 |
| `npm run backend:sepolia` | 读取 `.env.sepolia`，在端口 8000 启动使用 `.local/sepolia/` 的独立后端；不部署合约。先停止占用端口的其他后端 |
| `npm run test:browser` | 独立 Chrome / FastAPI / SQLite 一致性回归，不访问 Sepolia |
| `npm start` | 启动 Sepolia 后端与前端；已有 NFT 清单时才启动监听，不自动部署 |
| `npm run start:demo` | 连接 Sepolia，开启链下测试菜单；拒绝复用占用端口的旧服务 |
| `npm run chain` | 只读检查 Sepolia 节点 |
| `npm run deploy` | 同 deploy:console，启动 Sepolia 工作台，不自动发送交易 |
| `npm run test:contracts` | 运行现有合约测试 |
| `npm run test:backend` | 运行现有后端测试 |
| `npm run verify:game` | 在隔离环境验证当前游戏/NFT 闭环；目前不覆盖未来充值和质押功能 |

独立监听命令 `npm run indexer`、`npm run indexer:sepolia` 已实现，追加 `-- --once` 可补查后退出；`npm run chain:record` 是保留的旧本地工具，只读补全本地 NFT 清单，不用于建立 Sepolia 部署。具体配置与恢复限制见[链上监听与恢复](链上监听与恢复.md)。通用 Sepolia 首次部署入口已实现；业务合约部署和资金恢复仍待实现。
