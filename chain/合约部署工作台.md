# 合约部署工作台 · Sepolia

更新日期：2026-10-30。日常部署使用 **Ethereum Sepolia（11155111）+ MetaMask**。

默认模块为 `ForgeOfFate`：包含武器 NFT 与 ETH 交易市场，卖家自行定价、改价、撤单并提取成交收益。游戏币仍由服务器保存；充值、质押和 NFT 换回武器暂未接入。可选 `DeploymentProbe` 仅用于验证部署流程，原计划单独保留。

NFT 独立计划、授权密钥、最终确认和游戏配置交接已通过隔离测试，**不代表已完成真实 Sepolia 部署或 MetaMask 验收**。游戏 NFT 交易页面已补最终确认与已知哈希的持久恢复；加速/取消及未拿到哈希的广播恢复仍待完善，不能将工作台能力视为游戏页面已有能力。图片统一使用项目[公开图片映射](../assets/NFT_Pic/README.md)。

## 1. 启动和部署

1. 安装依赖 `npm ci`。本机真实配置填写在根目录 `.env.sepolia`；新机器从空白 `.env.sepolia.example` 复制，已有配置不要覆盖。
2. 填写项目钱包公开地址 `PROJECT_WALLET_ADDRESS` 和服务商提供的 `SEPOLIA_RPC_URL`。钱包私钥、助记词不填写到项目。项目钱包需要有 Sepolia 测试 ETH 支付 Gas。
3. 运行 `npm run check:sepolia` 可先做只读检查；运行 **`npm run deploy:console`**（或 `npm run deploy`）启动工作台。
4. 在装有 MetaMask 的桌面浏览器打开 **http://127.0.0.1:5174/deploy**。选择配置中的项目钱包，点击“连接 MetaMask / 切换网络”，确认网络为 **Ethereum Sepolia**。若钱包尚未显示该网络，在 MetaMask 中开启“显示测试网络”并选择 Sepolia。页面不会将私密 RPC URL 传给钱包。
5. 核对项目钱包、网络、合约名 `ForgeOfFate`、铸造授权地址、发送金额和部署内容指纹，点击“部署到 Sepolia”。在 MetaMask 核对手续费并确认。向合约发送的金额为 0 ETH，手续费消耗 Sepolia 测试 ETH。
6. 页面依次显示等待打包、等待最终确认；达到节点的 `finalized` 边界后才显示成功、保存合约地址和部署记录。交易链接可在 Sepolia Etherscan 查看。
7. NFT 模块自动保存游戏的版本 2 清单 `.local/sepolia/deployment.json`；可下载同一份公开部署记录。重启游戏服务（`npm start` 或 `npm run start:demo`），再刷新游戏页面，启动器会读取合约并启动监听。
8. 关闭终端只停止本机服务，Sepolia 合约仍在；再次运行同一命令继续原计划和交易。保留整个 `.local/sepolia/`。

首次准备 NFT 计划时，会生成专用服务器铸造授权密钥并保存到 `.local/sepolia/mint-key`（权限 0600）。这与 MetaMask 的钱包私钥不同，只用于核准游戏武器，页面仅显示授权地址。已有计划时密钥丢失或不匹配会停止，不会重新生成密钥冒充原授权方。

需要继续原 Probe 计划时，先关闭当前工作台，再运行：

```sh
npm run deploy:console -- --module deployment-probe
```

两个模块共用页面和端口，计划目录互相独立。Probe 不写入游戏 NFT 清单，也不是部署 NFT 的前置步骤。

应用不自动发币、不启动 Hardhat 节点、不在后台代签或部署。真实配置和 `.local/` 不提交 GitHub；源码、锁文件、空白模板和说明可以提交。

## 2. 日常游戏服务

- `npm start`：启动使用 Sepolia 配置的游戏后端和前端，地址 http://127.0.0.1:5173/。
- `npm run start:demo`：同样连接 Sepolia，并开启已有的链下测试菜单；需要该环境的测试账号。
- `npm run backend` / `npm run backend:sepolia`：单独启动 Sepolia 后端。
- `npm run indexer` / `npm run indexer:sepolia`：监听已有的 Sepolia NFT 部署。缺少最终确认的 NFT 部署信息时不能启动索引；Probe 记录不会被当作 NFT 清单。

NFT 功能在完成真实部署并重启游戏后进行人工验收；充值仍未开放。普通强化、仓库、账号和游戏币消费仍由本机后端处理；“使用 Sepolia”不把这些普通操作改成收费交易。

日常游戏使用独立 `.local/sepolia/game.sqlite3`。旧 `.local/game.sqlite3` 保留，不自动复制账号、武器或余额到新环境。进入 Sepolia 环境需要在该环境注册/登录；需要本机测试账号时可显式运行 `npm run accounts:setup`，它只在 Sepolia 存档中创建缺少的测试账号，不重置已有账号。

游戏启动器占用 8000/5173，工作台占用 8010/5174，均仅绑定 `127.0.0.1`。启动器拒绝复用其他已占用端口的服务，避免连接错网络。游戏与工作台可以同时运行，分别在对应终端 Ctrl+C 停止。

## 3. 持久化与恢复

NFT 部署记录固定保存在（Probe 使用同级 `deployment-probe/`）：

```
.local/sepolia/deploy-console/forge-of-fate/
```

| 文件 | 用途 |
|---|---|
| `plan.json` | 已固定的项目钱包、网络、ABI、授权地址、构造参数、创建内容、部署标识与编译资料指纹 |
| `build-info.json` | 本轮编译输入/输出、源码和编译器信息，供之后核验和源码验证 |
| `state.json` | 当前意图、交易哈希和处理状态；运行中持续保存 |
| `deployment.json` | 最终确认后生成的地址、交易、区块及代码哈希、ABI |
| `compile.log`、`frontend.log` | 本机日志 |

保留整个目录。重启读取原计划，不重新生成部署标识或覆盖已有记录；配置中的钱包与原计划不符时拒绝启动。API 的固定独占端口确保同一工作台只启动一份服务，进程意外退出后端口由系统释放。编译源码更新不会自动替换已固定的计划；如需更换合约，应另行设计明确的部署与迁移流程；不要删除旧计划重来。

状态为 `ready → awaiting_wallet → submitted → confirming → confirmed / failed`。本机服务关闭期间，已提交的交易仍可在 Sepolia 打包；服务重新启动后根据保存的哈希继续核验。

- 明确拒签后可以重新发起。回复不确定时保留待处理状态，不自动再次发送。
- 浏览器先保存钱包返回的交易哈希，再提交后台。刷新不会重发；后台未收到时，可在页面粘贴 MetaMask 活动记录中的哈希恢复。
- 钱包“加速”产生的新哈希可用于恢复，必须与原交易使用相同序号和部署内容。钱包取消交易不属于部署成功，不能用无关交易冒充回执。
- 执行失败也要等最终确认，之后才允许重试，防止根据尚可变化的区块重复花费。
- 节点暂时不可用时展示原待处理记录，但禁用新部署；可以保留哈希后重试查询。已确认的记录核验失败时不再显示有效成功状态，文件保留供排查。
- 如果在钱包确认期间关掉页面，先到 MetaMask 检查是否已发出交易；有哈希则恢复。没有证据时不要删除计划或状态来重新部署；关闭再启动也不会清空这个意图。

验证包括链 ID、创世区块、部署者、创建交易类型、完整创建内容、0 ETH 金额、规范链区块哈希、`finalized` 边界、合约地址推导和代码。节点不支持最终确认查询时不降级为最新区块。

NFT 模块另核对合约的 `mintSigner()`、`deploymentId()` 与本机密钥、固定参数一致，再生成版本 2 清单。先保存本轮记录，再原子写入游戏清单；中途退出可在重启后继续。游戏已有不同清单时停止且保留原文件，不自动覆盖。工作台显示成功代表配置已保存，首次部署后仍需重启游戏来启动监听。

Probe 清单与 NFT 监听清单分开，不能复制到 `.local/sepolia/deployment.json`。当前未自动完成 Etherscan 源码验证；`build-info.json` 留作验证材料。

## 4. 验证方式

当前工作台和游戏入口已用真实 Sepolia RPC 做只读检查。实际部署仍由使用者在 MetaMask 中确认，自动回归不代付测试币：

```sh
npm run test:deploy:service
npm run test:deploy
npm run build
```

第一项包含 12 项模拟 Sepolia RPC / 文件恢复检查，覆盖最终确认、密钥匹配、固定编译资料、配置冲突和写入中断恢复。第二项包含独立本地链的 6 项公共流程检查、1 项 NFT 部署与实际铸造 / 后端 / 监听交接检查，以及使用模拟响应的 2 项 Sepolia 页面检查。它们是开发用的隔离自动测试，不是实际操作入口，也不能代替 MetaMask + Sepolia 的人工验收。原有本地工具仅保留在明确的 `*:local` 命令和测试目录中，日常命令不会自动切回它们。

人工验收：确认 MetaMask 显示 Sepolia；拒签一次检查不会部署；确认后在 Etherscan 核对回执；刷新页面和重启本机服务后地址/交易不变。NFT 部署后重启游戏，继续进行铭刻、双钱包挂牌 / 购买 / 提现及停机补扫验收。充值不在本轮范围。

网络与最终确认语义参考[以太坊 JSON-RPC 文档](https://ethereum.org/developers/docs/apis/json-rpc/)，钱包切换参考[MetaMask 网络管理](https://docs.metamask.io/metamask-connect/evm/guides/manage-networks/)。
