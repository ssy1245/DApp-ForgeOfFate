# Forge of Fate · 开发前填写清单

更新日期：2026-10-28。先准备 Sepolia 和钱包连接信息，不需要现在决定充值价格或质押产币速率。

## 1. 现在填写在哪里

填写项目根目录的 **`.env.sepolia`**。本机配置文件已准备；其他机器可复制 [`.env.sepolia.example`](../.env.sepolia.example) 创建。这份实际配置由 Git 忽略，公开模板只保留空值并随源码提交 GitHub。

当前统一使用[Sepolia 部署工作台](合约部署工作台.md)：`npm run deploy:console` 使用已填的项目钱包和 RPC；需要项目钱包持有 Sepolia 测试 ETH 支付手续费，私钥仍留在 MetaMask。

| 字段 | 现在是否必填 | 填什么、从哪里取得 |
|---|---|---|
| `PROJECT_WALLET_ADDRESS` | 必填 | 从 MetaMask 复制项目钱包公开地址，以 `0x` 开头。已确定部署和收款先使用同一个钱包，所以只填一次。 |
| `SEPOLIA_RPC_URL` | 必填 | 从 RPC 服务商项目中复制 Ethereum Sepolia 的 HTTP(S) 连接地址，供本地服务器读取链上数据。它不是钱包地址，也不是区块浏览器页面地址。 |
| `DEMO_BUYER_ADDRESS` | 可暂时留空 | 第二个测试钱包的公开地址，用于演示一个钱包卖、另一个钱包买；必须与项目钱包不同。 |

填写形式为 `字段名=内容`，保留文件中的字段名，不用填写尖括号或额外说明。项目钱包地址不是部署完成后生成的合约地址。

RPC 地址可能包含服务商 API 密钥，保存在本机配置即可，不需要发到聊天或放进 README。钱包私钥、助记词、钱包密码不属于本次准备资料，不填写到这个文件。计划由 MetaMask 确认部署与玩家交易；连接配置不赋予程序签名或转款能力。

## 2. 钱包里需要准备什么

- 项目钱包：在 MetaMask 中确认使用 Sepolia，并准备 Sepolia 测试 ETH，用于后续部署和测试交易的 Gas。
- 第二个演示钱包：双钱包购买演示前准备，购买时还需要支付 NFT 价格和 Gas。
- 项目钱包同时负责部署和收款；另一个演示钱包用于买方角色，不需要再单独创建一个收款钱包。

测试 ETH 可以从[以太坊官方 Sepolia 水龙头列表](https://ethereum.org/developers/docs/networks/#sepolia)选择入口领取。主网 ETH 或其他测试网余额不能替代 Sepolia 余额。当前不预设一定够用的金额，后续按实际部署和交易估算费用。

如果还没有 RPC 地址，可以先填写项目钱包地址，节点服务稍后配置。MetaMask 已能使用 Sepolia，并不代表我们已经取得了供后台使用的节点接口。

例如可以按 [Infura 官方入门说明](https://docs.infura.io/get-started/infura/)创建 API 密钥，再在网络端点中选 Ethereum Sepolia 的 HTTPS 地址；[端点列表](https://docs.infura.io/get-started/endpoints/)可用于核对。不要直接使用教程中的 Mainnet 示例地址，也不要选到其他链的 Sepolia 测试网。

## 3. 填写后怎么检查

安装项目依赖后，在项目根目录运行：

```sh
npm run check:sepolia
```

检查器只读取 `.env.sepolia`，检查地址格式，并发送只读的 `eth_chainId` 和 `eth_getBlockByNumber(finalized)` 请求，确认返回 Sepolia（11155111）且支持最终确认边界。不会部署合约、发送交易、生成私钥或改动现有游戏存档，也不会打印 RPC 地址与服务商响应内容。

仅检查格式、暂时不连接网络时运行：

```sh
npm run check:sepolia -- --offline
```

缺少配置或格式错误会列出需要修正的字段；节点不通或网络错误会提示检查失败。检查通过不等于已经验证钱包控制权、余额、历史日志服务能力或合约部署。

**当前 `npm start`、部署工作台、检查器和 Sepolia 后端/监听器都会读取这份配置。** 游戏与部署记录使用 `.local/sepolia/`，启动不会自动部署，也不复制旧本地存档。前端只接收公开网络信息，不接收私密 RPC。填写完成和节点检查通过不等于已经部署合约。
