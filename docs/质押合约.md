# NFT 质押合约与监听接入

## 本轮状态

`ForgeStaking` 合约、RPC 事件解码、持久监听、每日奖励邮箱和部署工作台已经接通，并完成独立本地链演练。**Sepolia 部署交易已提交，等待最终确认与清单保存。** 已按用户选择在本机设置每日 1000 游戏金币；首次监听登记后冻结费率。游戏“命运集市 → NFT 质押”已提供单枚授权、质押、取回和待确认交易恢复。

## 合约规则

- 仅托管构造时指定的 `ForgeOfFate` NFT，收藏集合和部署身份不可更换。
- NFT 持有人先 `approve(stakingAddress, tokenId)`，再调用 `stake(tokenId)`。被授权的其他钱包不能替持有人建立质押。
- `stake` 将 NFT 转入合约，产生独立 `positionId`，发出 `Staked(positionId, staker, tokenId, startedAt)`。同一 NFT 不能重复质押，转入会清除原市场挂单。
- 质押人可随时调用 `unstake(positionId)`，取回同一 NFT，发出 `Unstaked(positionId, staker, tokenId, endedAt)`。不需要服务器许可，不需要退还游戏金币；没有管理员扣留、暂停取回或提走资产的入口。
- 接收钱包拒绝 NFT 时整笔取回交易回滚，原仓位继续有效。回调不能重入质押或取回。再次质押使用新的编号，旧仓位不可重新领取或取回。
- 只接受 `stake` 内部触发的预期 ERC-721 接收回调。直接 `safeTransferFrom` 会拒绝；ERC-721 的非安全 `transferFrom` 无法被接收方拦截，误转不形成仓位也不产奖，当前没有此类误转资产救回入口。游戏必须使用 `stake`，不能用转账代替质押。
- 合约不收 ETH、不发行 ERC-20、不保存游戏币费率。每把每日费率由服务器配置，按 UTC 有效秒数折算到邮箱；详见[奖励邮箱](奖励邮箱.md)。

## 部署前验证

```sh
npm run test:contracts
npm run test:backend
npm run test:deploy:service
npm run test:staking
```

最后一项自动使用临时端口、临时数据库和 Hardhat 公共测试账号：部署真实本地 NFT 与质押合约，质押后暂停监听，链上取回并推进时间，再重启 Python 监听，经 RPC 解码生成每日邮件，通过真实邮件 API 领取并重试，最后清理临时节点和数据。不会使用 `.local/sepolia`、浏览器钱包或公开链测试币。

固定案例：UTC 中午开始，两天后的中午取回，每日 100 游戏金币（仅演练参数）。正确结果为 50、100、50 三封邮件，总额 200；四天后重启仍只有 200，再次重启或重复领取不增加余额。

## Sepolia 部署与质押入口

1. 保留已有 NFT 部署和存档，确认 `.local/sepolia/deployment.json` 是当前 NFT。关闭原先占用 5174 / 8010 的部署工作台；不需要关闭正常游戏页面。
2. 运行 `npm run deploy:staking`，打开 `http://127.0.0.1:5174/deploy`。页面显示 `ForgeStaking` 与关联 NFT 地址。构造参数固定为当前 NFT 地址和新的质押部署身份，不需要 NFT 铸造密钥。
3. 核对网络、项目钱包和关联 NFT 后，由用户在 MetaMask 确认部署。工作台等待 Sepolia 最终确认，核对合约身份和 NFT 收藏集合，再保存 `.local/sepolia/staking-deployment.json`；不会覆盖原 `deployment.json`。
4. 在 `.env.sepolia` 明确设置 `FORGE_STAKING_COINS_PER_DAY` 为正整数。模板的 0 表示尚未配置，阻止登记来源。首次监听固定此费率，修改配置不会覆盖旧奖励规则；不要靠删除结算表调价。
5. 重启正常启动器 `npm start` / `npm run start:demo`，或在独立运行方式下重启 `npm run indexer:sepolia`。不要启动重复监听进程。
6. 回到游戏并刷新状态，使用实际持有 NFT 的已绑定账号和钱包，进入“命运集市 → NFT 质押”。页面展示已登记费率后，先点击“授权此 NFT”并在钱包确认；等待最终确认后点击“确认质押”，再确认第二笔交易。授权本身不计奖。已有挂单会在质押转入时清除。
7. “质押中的 NFT”显示实际仓位与开始时间，可点击“取回 NFT”结束。取回不依赖奖励费率，仍需正常钱包和节点读取；失败交易不改变仓位。pending 记录区分 NFT 与质押合约，刷新不会重复发送。
8. 北京时间每日 08:00 是 UTC 零点；跨日并等待最终确认后，监听按前一日实际质押秒数发送奖励邮件。今晚仅质押部分时长，首封不足 1000 金币是正常折算，不是漏发。关闭服务不会停止链上质押，次日重启会补处理。
9. 测试账号的链上诊断会显示质押部署核验、最终确认和监听结算状态。游戏邮箱沿用现有未读提醒、单封和一键领取。

部署工作台自己的计划/回执位于 `.local/sepolia/deploy-console/forge-staking/`。刷新、关闭后恢复时沿用原计划；构造参数、编译记录或 NFT 部署改变时拒绝继续。公开交接只需要质押部署清单以及 README 配置说明；RPC 凭据、数据库和私钥不上传 GitHub。

## 监听与故障恢复

`RpcStakingSource` 使用固定的 Staked / Unstaked 事件定义，核验当前 NFT 环境、质押合约收藏集合、部署身份、部署回执、创世块和运行代码摘要。Sepolia 只接受 `finalized` 边界，节点不支持时不退回 latest。

每批区块连续处理，包括空区块范围；核对事件区块哈希、日志顺序和事件时间与区块时间。部署未最终确认前不登记产奖仓位。保存进度后发生区块冲突、部署切换或配置丢失时暂停，不自动清除证据或重新发奖。查询失败保留原进度，下次缩小查询范围或重试。

监听只结算已完整处理的最终确认区间。停机期间质押、取回都可以发生，恢复后先补事件，再按真实起止时间结算。长期离线每批最多结算 30 个日历日；最后结算边界、余数、邮件去重身份和领取流水全部持久保存。
